# 配图 MVP 规格

Status: draft — 用户于 2026-10-10（Halifax）确认下一 EPIC 拆分；新策略尚未实施。

## Problem Statement

现有配图交付需要更好地连接文章内容、可取得的真实图片、生成插画与双语稿。读者需要图片既帮助理解真实信息，也提供氛围、隐喻、幽默和阅读节奏；跨平台封面与风格选择也需要形成一致、可读的交付。

## Solution

复用现有图片规划和交付路径，按文章内容组合合适的源图与生成图，并交付到双语 Markdown。默认源图与生成图混搭；Agent 主动寻找贴题源图，按文章需要决定数量和组合，Deep 不默认全生成。没有合适素材时可不含源图并记录，或收窄表达，不硬凑。LinkedIn、知乎和微信默认共用一张无字、不叠标题或 Caption、不裁切的封面。先决定内容与画面表达，再选风格；结合可取得的近期文章封面减少视觉相似，同时不强制轮换。程序只负责素材安全、取得、路由、交付和失败保稿，不审核创作成果。

## User Stories

1. 作为读者，我希望图片能解释文章中的真实信息，也能提供氛围、隐喻、幽默或阅读节奏，让文章更容易理解和阅读。
2. 作为编辑，我希望源图与生成图按文章需要混搭，以便图片适合实际内容而非固定配额。
3. 作为编辑，我希望系统主动寻找贴题源图，不因 Deep 模式而把所有图片都生成为插画。
4. 作为编辑，我希望缺少合适素材时可以收窄表达或省略细节，以免硬凑图片。
5. 作为读者，我希望真实测试、Demo 或社区截图保持真实来源，不被生成图冒充。
6. 作为编辑，我希望 LinkedIn、知乎和微信共用一张无字封面，以便同一文章保持一致。
7. 作为读者，我希望封面不叠加标题或 Caption，也不因平台适配而裁切。
8. 作为编辑，我希望封面可以复用合适的已有图片或生成图，以免无必要地重复生成。
9. 作为编辑，我希望来源和 Alt 等素材信息沿用既有交付方式保存，方便识别图片来历与用途。
10. 作为编辑，我希望先从文章内容决定画面表达，再选择视觉风格，让风格服务于内容。
11. 作为编辑，我希望风格库说明不同风格适合表达的内容与气氛，并在规划中描述主体、构图、配色和手法。
12. 作为编辑，我希望源图保持原有真实内容，不为了统一风格而被重画成看似真实的测试或界面。
13. 作为编辑，我希望参考最近三篇不同文章的封面，减少材质、构图或颜色上的相似，同时允许适合时沿用同一风格。
14. 作为编辑，我希望双语版本共用封面时只按一篇文章计入近期参考。
15. 作为编辑，我希望历史少于三篇时使用现有历史；无历史或无法读取时正文仍可交付。
16. 作为编辑，我希望系统只参考实际取得的封面图片或可靠视觉摘要，不把 URL 当成已经看过图片。
17. 作为编辑，我希望图片取得或生成失败时保留正文、双语版本和保存状态。
18. 作为编辑，我希望能在最终双语 Markdown 中检查图片和图注是否可读、图片是否可打开。

## Implementation Decisions

- 复用现有视觉规划、源图下载、图片生成、上传与双语 Markdown 组装路径；不引入新服务或新依赖。
- 默认允许源图与生成图混合，图片数量和组合由文章需要决定；无合适素材时允许收窄表达。
- 共享封面采用已有合适图片或生成图片；平台复用同一资产，不叠字、不裁切。
- 规划过程按内容、画面表达、风格推进；丰富风格库需有用途与气氛说明，计划包含主体、构图、配色及手法。参考源项目的内容先行、视觉机会和画面具体化方法，转写为本项目自拟指导；源项目流程不作为本项目验证结果。详见[研究摘要](../../docs/research/ai-daily-visual-reference-kb-2026-10-10.md)。
- 近期封面参考最多取最近三篇不同文章，只参考实际封面图像或从实际图像读取的可靠视觉摘要；旧 prompt 仅辅助创作意图，不是视觉参考。历史不足时用已有图像；读取历史失败时保留正文并如实注明未参考，不新增检索、评分、轮换或历史账本。不得用 URL 或文字标签假装看过图。
- 保持源图原貌与来源信息；不得生成并冒充真实测试、Demo 或社区截图。
- 保留 URL 安全、素材可用性、错误处理和失败保稿；不以程序判断创作质量。
- 具体实现触点、切片状态与历史运行证据见执行计划及 EPIC 草案，不在规格中绑定具体路径或代码。

## Testing Decisions

- 以保存稿件到最终双语 Markdown 的最高现有局部入口观察外部交付行为；只检查本次切片所影响的边界。
- 使用实际取得的图片或可靠视觉摘要验证规划输入；裸 URL 不构成图片理解证据。
- 检查共享封面是否无字、未裁切，双语是否复用同一资产；检查图片可打开、图注可读及失败时正文保留。
- 人工阅读只判断读者能否理解交付，不做创作评分。模型单次成功不证明稳定效果；节点成功或候选数量也不等于图片采用成功。
- 复用有效回执，不为重复证明同一分支而重跑全链。

## Out of Scope

- 创作程序审核、评分或排名 Agent。
- 固定图片数量、字数、来源配比或强制风格轮换。
- 合同、审计、逐句证据链、风格评分、检索系统或历史账本。
- 生成图片冒充真实测试、Demo、界面或社区截图。
- 新建图片搜索/视觉服务，或静默更换模型、provider、harness。
- 将本项 n8n 工作迁移到 Codex-native；该迁移属于独立任务。
- 自动发布、发邮件、生产发布或凭据变更。
